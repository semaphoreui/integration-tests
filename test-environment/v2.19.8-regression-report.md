# Semaphore v2.19.8: terminal task status опережает output/stage persistence

- **Дата проверки:** 2026-08-19
- **Версия:** `semaphoreui/semaphore:v2.19.8` (`3449a04f3bfa2522ec7fd60803f71b578c39f6b4`)
- **Статус:** воспроизводимая lifecycle-регрессия
- **Компонент:** task runner / task logger / task output persistence

## Кратко

Semaphore может опубликовать terminal task status (`success` или `error`) раньше, чем завершится запись output/stages. Клиент, который после terminal status сразу читает output, получает неполную диагностику или обрезанный вывод успешной задачи.

## Сценарий 1: потеря Git stderr

1. Создать repository с несуществующей веткой `bookwright-missing-ref`.
2. Запустить template и дождаться task status `error`.
3. Сразу прочитать `GET /api/project/{project_id}/tasks/{task_id}/output`.

Ожидается: output содержит clone failure и имя проблемной ветки.

Фактически в неуспешных прогонах:

```text
Cloning Repository file:///fixtures/ansible
Failed updating repository: exit status 128
Failed to run task: exit status 128
```

Имя ветки и stderr Git отсутствуют. В пяти принудительных повторах на SQLite сценарий упал 3 раза. Такое же падение получено в полном SQLite core run и production-like run с `semaphoreui/runner:v2.19.8`. PostgreSQL, MySQL и MariaDB core runs в этой серии прошли, что подтверждает недетерминированность.

## Сценарий 2: `success` до финализации output

Upgrade-профили SQLite и PostgreSQL:

1. Создают связанный fixture на `v2.19.7`.
2. Перезапускают server на `v2.19.8` с той же БД.
3. Успешно читают project, access key, repository, inventory, template, schedule и старый task output.
4. Повторно запускают сохранённый template и дожидаются `success`.
5. Сразу читают task output.

В обоих dialect output обрывается после:

```text
PLAY [Semaphore test fixture] **************************************************
```

Ожидаемый marker `semaphore-bookwright-smoke-ok` и play recap отсутствуют, хотя task уже имеет `success`.

После удаления task в test cleanup server продолжает записывать stage и логирует:

```text
SQLite: constraint failed: FOREIGN KEY constraint failed (787)
PostgreSQL: insert or update on table "task__stage" violates foreign key constraint "task__stage_task_id_fkey" (23503)
```

## Ожидаемый контракт

- terminal task status публикуется только после записи всего output и stages;
- сразу после terminal status API возвращает полный стабильный output;
- после удаления terminal task нет поздних записей в связанные таблицы и FK errors;
- Git clone failure сохраняет stderr, необходимый для диагностики.

## Команды воспроизведения

```bash
test-environment/profile up core-sqlite-local
test-environment/profile test core-sqlite-local --no-daemon --rerun-tasks \
  --tests io.bookwright.tests.semaphore.RepositoryGitTest.missingBranchFailsWithUsefulOutput

test-environment/profile upgrade-test upgrade-sqlite-local
test-environment/profile upgrade-test upgrade-postgres-local
```
